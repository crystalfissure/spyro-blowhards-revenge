# Bull and Toreador

UE 4.27.2 assets:

- `/Game/OT_Ports/S1/S1_Enemies/Home_00_Artisans/03_TownSquare/Bull_BP`
- `/Game/OT_Ports/S1/S1_Enemies/Home_00_Artisans/03_TownSquare/Toreador_BP`

Both derive from the project's `Base_Enemy_BP`. Their behavior and animation classes are in `SpyroGameplay`; `SpyroEditor` supplies configuration and isolated test helpers. All ten source animation takes per enemy, textures, skeletons, materials and nine original sound samples are saved game assets. Runtime needs neither the research folder nor Blender, Python, an emulator or the original disc. Use the repository's UE 4.27.2 Windows editor binaries, or rebuild the included source for another engine/toolchain. The normal project and shared Spyro dependencies still apply.

## Placement

The 1 October 2026 correction guards Toreador's reaction completion by its actual reaction clip. A Bull arriving on the preceding idle/attack clip's completion update no longer skips the reaction. Focused native checks cover that transition and normal reaction completion; route authoring defaults and movement speeds are unchanged.

Place either Blueprint with its capsule resting on blocking ground (root approximately 92 cm above a horizontal floor at default scale). They work independently. To create a pair, select the Toreador's **ToreadorBehavior** component and explicitly assign **Town Square > Pair > Linked Bull** to the placed Bull. Leave it empty for standalone cape combat. There is no nearest-enemy pairing. Each Bull accepts one Toreador; `Pair Conflict` and `Validate Placement` expose invalid assignments. Destroying a partner clears its reciprocal runtime link. Defeating one changes the surviving member's behavior without deleting the authored assignment, so checkpoint reset can restore the pair.

The Toreador's explicit link controls the Bull's movement; no separate movement selector is needed:

- An **unpaired Bull** runs back and forth along its placed forward arrow, brakes/turns at its endpoints, and resumes its patrol after a horn attack. **BullBehavior > Town Square > Patrol > Patrol Distance** sets the total distance, centred on its placement (default 1,200 cm). Old Bull waypoint overrides no longer affect its movement.
- A **paired Bull** copies the Toreador's route, orientation, starting center and radius, then follows the closed circuit. This also works when an explicit link is added during play.
- A Bull keeps that established circuit if its Toreador dies or is destroyed. Explicitly clearing or changing a surviving Toreador's link instead restores the Bull's straight patrol. Checkpoint reset preserves the established route and restores the pair's health-dependent behavior.
- **Active Movement Pattern** is a runtime diagnostic. Older serialized movement selections are retained for asset compatibility but no longer override pairing.

All spline and waypoint authoring belongs to the Toreador. The Bull has no editable route points, route yaw, roam radius or spline preview. Its runtime copy of a linked Toreador's circuit survives the loss of that actor. For a legacy waypoint circuit, the Toreador's radius defaults to 1,800 cm and cannot be smaller than 300 cm. Place both members inside the territory with body clearance.

### Editable Toreador run path

The Toreador Blueprint includes a real **RunPath** Spline component, using the same viewport point/tangent controls as the Egg Thief's Spline component. On a placed Toreador, enable **ToreadorBehavior > Town Square > Route > Use Run Path**, then select **RunPath** in Components. Move its points, Alt-drag to add points, and use the spline point menu to choose curved or linear segments and edit tangents. Keep **Closed Loop** enabled and set **Linked Bull** on ToreadorBehavior. You can also edit the Blueprint's default RunPath for future placements.

Spline coordinates use Unreal centimetres and the component's transform. **Route Points**, **Route Yaw** and the legacy circular **Roam Radius** are hidden while Use Run Path is enabled and do not scale or clip that spline. Author the curve around obstacles and over supported ground: movement still uses collision sweeps and terrain projection. Both enemies follow the actual curve, including custom tangents. The path is captured in world space when play starts, so it stays fixed while the Toreador moves. A newly linked Bull gets an internal runtime copy, which survives Toreador death/destruction; explicit unlink restores its straight patrol. Checkpoint reset restarts their progress on the same captured curve.

**Use Run Path** defaults off to preserve existing authored waypoint placements. A missing, open or zero-length spline reports a placement warning and falls back to the legacy route. **Following Run Path**, **Run Path Distance** and **Run Path Length** expose the active runtime route in Debug. No NavMesh or additional path actor is needed.

Legacy Toreador route points are local coordinates in original-game units, converted by `0.146104` cm per unit and rotated by its placed yaw plus Route Yaw. The default three points reproduce the first Town Square pair's route. Routes are uniformly reduced when necessary, reserving body and turning clearance. Z follows blocking terrain. Only the Toreador shows an editor route preview; **Draw Movement Debug** shows runtime paths. Existing Toreador waypoint values keep their property names and load unchanged after moving the authoring properties out of the shared behavior class.

No NavMesh is needed. Author routes around obstacles and avoid narrow dead ends. Sweeps, bounded sliding against walls, ground support probes and a circular boundary constrain movement; repeated terrain obstruction reverses route direction. Player contact stops movement and does not reverse the circuit or slide the enemy around Spyro. These safeguards do not provide general pathfinding. Arbitrary nonuniform actor scaling is not a supported placement workflow.

Explicitly linked partners ignore one another in their own movement sweeps and terrain probes, so their collision boxes cannot deadlock the shared route. Their blocking/charge collision with Spyro remains enabled. Unlinking or destroying a partner removes the movement-ignore relationship.

## Combat and reset

The behavior uses the existing Damageable, Drops Items, player damage and checkpoint contracts. Bull charge immediately awards its one reward and transitions through inversion to horns-stuck behavior. Repeated charge cannot award another gem. Flame removes an active or stuck Bull; flame after charge does not pay again. Toreador charge and flame both use its death reaction and one reward. The default reward is one green gem, matching the first reference pair; change the inherited dropper's **Items to Drop** first entry to choose a different gem value. Additional array entries are not emitted by these one-reward enemies.

Bull horn contact is active on frames 3–5 of its attack, aligned with the thrust/vocal cue. It requests Spyro's existing **Ram** damage reaction: a 600 cm/s outward launch plus 300 cm/s upward recoil, using the existing airborne hurt, landing and health/invulnerability logic. The direction points away from the Bull at contact. The Toreador retains ordinary cape damage and its ground-level recoil. A Bull adds a short `S1_HitWall` contact impact to Spyro's native hurt sound only when health actually decreases; a miss or invulnerable target produces no extra contact sound. **BullBehavior > Town Square > Gore** exposes the impact asset, volume and pitch (defaults 0.65 and 1.05). The attack vocal cue can still play on a miss. Charging Spyro retains contact priority.

The Bull begins a gore only within the same 1,536-original-unit reach used for contact (about 224 cm), within a 60-degree half-cone, on comparable ground height and with clear line of sight. It turns toward Spyro during the wind-up and commits its facing for the thrust, so stepping away can still dodge. During its one-second recovery it waits if Spyro remains directly ahead, then retries; it does not run against his body throughout the old four-second cooldown. A nearby charging Spyro bypasses this attack arbitration and reaches the native charge sensor.

The Toreador reacts and runs along its circuit when its live Bull approaches within 4096 original units (about 598 cm). It stops at home or when more than 6144 units (about 898 cm) clear of the Bull, and runs again when approached. This separation between start and stop distances prevents rapid state changes near a single threshold. Without a live Bull, including after charge incapacitates it, the Toreador stops moving, plays its idle animation and slaps nearby Spyro with its cape. The attack requires Spyro within 2048 units (about 299 cm) and at a comparable ground height; its active frames, facing, obstruction and damage checks remain in force.

A surviving loop Bull continues its route after the Toreador's defeat. Root physics launches and the inherited generic walking/attack controller are disabled only on these actors. Frame-driven sounds stop during reset/cleanup. Checkpoint reset restores health, collision, starting transforms, animation state, reward guards and pair behavior while retaining the Bull's movement pattern and patrol center; gem identity and permanent collection filtering remain with the shared project dropper.

## Reference basis and fidelity limits

The reference is the local NTSC Spyro 1 Town Square disc data and the public decompilation at commit `46b51d3a5c34dd2585b4fe1de74ac9b74c76390d`. All 9,849 assembly words in the consulted level update listing matched that disc's overlay. Model classes are Bull 23 and Toreador 395. Independently decoded model scales are 2 and 4. Animation counts, original per-update interpolation, sound tables/pitches and the cape collision-active frames (5–7 of Anim8) were inspected directly. The implementation advances at 30 Hz and interpolates presentation between updates.

The original Bull configuration has a movement field independent of its partner reference. Four Town Square Bulls use two-node patrols, two use linked three-node circuits, and two select player pursuit. Route following is therefore intentional for the linked variant; a direct chase toward the Toreador is not the basis of this port. The requested UE design simplifies authoring to an unpaired patrol overridden by a linked Toreador's circuit; it does not expose that original independent player-pursuit variant. The original linked branch also contains a conditional partner-state/home-distance transition into patrol mode, not player pursuit. The exact helper and that transition are not emulated here; the UE loop retains its authored circuit after partner death.

This is a source-informed UE port, not a verified bit-identical emulation. Authored waypoint steering, circular containment, floor support, capsule/box collision and attack range/cones adapt the behavior to UE terrain and Spyro's existing collision contracts. The original route helper, exact collision volumes, SPU reverb/mixing, random state timing and every branch of the original state machine have not been proven equivalent. No synchronized emulator/gameplay comparison or listening review has been completed. Unused imported takes are retained rather than forced into the state machine. Multiplayer behavior is not validated.

The disposable `Bull_Toreador_Test` map, source audit, scripts, logs and screenshots are outside the game repository in `C:\Users\adace\Desktop\Scripts\bull_toreador_research`. See that folder's README and reports for test scope and results. The initial addition did not place enemies in production maps; the subsequent Artisans review adjusts the user's existing pair as described above.

## Physical contact and Blueprint feedback (3 October 2026)

The final Bull/Toreador damage check uses physical obstruction rather than the Visibility channel. A WorldStatic, WorldDynamic, PhysicsBody or Destructible surface blocks contact if it blocks either combatant's body object channel. Overlap-only triggers and camera/Visibility-only geometry do not block melee. The trace uses a shared body-height interval, rejects vertically separated bodies, and ignores the two combatants, their child actors and the existing explicitly linked partner. Range, cone, charge priority, attack frames and one-attempt-per-attack policy are retained. Attack awareness/wind-up checks retain their existing rules; this change protects final damage permission.

`OnEnemySignal` exposes attack commitment, recovery attempt and completed native reset notifications to Blueprints. See the signal table and callback rules in [README.md](README.md). It is suitable for optional encounter/presentation reactions; it does not replace native damage or motion.
